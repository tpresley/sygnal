# Sygnal: Other renderer targets: terminal, LLM agent, React Native, primitives, Web Worker

> A topic file of Sygnal's agent context. It assumes the core (`llms.txt`, or the sygnal-dev skill's `SKILL.md`: mental model, component anatomy, canonical forms, wiring rules, testing): read that first. Canonical forms only.

- Other renderer targets, the same components (intents must select controls to be portable; every target makes the DOM's events): a terminal `runTerminal(App, { styles })` / tests `createTerminal()` + `t.press('Tab')` + `t.frame()` (`sygnal/terminal`), an LLM agent `const { ui } = runAgentUI(App); serveMcp(ui, { tools: agentTools(app) })` (accessibility snapshot + `ui_click` / `ui_type` / … tools, `sygnal/agent-ui`), React Native `<SygnalView app={App} />` (`sygnal/react-native`), one file for web + native + terminal with the primitives `View` / `Text` / `Pressable` / `TextInput` / `Switch` / `Image` / `ScrollView` / `List` (`sygnal/primitives`, RN style objects, `controls({ Add: Pressable })`), your own on `sygnal/host` https://sygnal.js.org/renderers/overview/
- Terminal apps (`sygnal/terminal`): `runTerminal(App, { styles, drivers, mouse: true })`; the views stay HTML and the terminal stylesheet is `[selector, style]` rules. A full-screen layout is boxes in that sheet: `['main', { display: 'flex', flexDirection: 'column', height: '100%' }]`, `['.body', { flex: 1, display: 'flex' }]` (a flex row whose items have `width: '40%'` / `flex: 1` / `border` lays them out side by side), `['.list', { width: '40%', border: 'round', overflow: 'auto' }]` (scrolls with a scrollbar, keeps the focus in view; the title is its `aria-label`), plus `padding`, `gap`, `color`, `background`, `bold`/`dim`/`inverse`, and `:focus` / `:focus-within` / `:checked` selectors. Native `<select>`, `<dialog>` (`ELEMENT: { showModal: Confirm }`: the focus moves in and stays in, Escape closes it, `DOM.close(Confirm)` hears it), `[popover]`, `<details>`, `<textarea>` and radio groups behave as in a browser; the footer shows what the keys do on the focused element. A list is one Tab stop (roving `tabIndex`, ↑ / ↓ inside it, prevent their default so the focus doesn't move on), so Tab reaches the next pane. Quit from the model with `QUIT: { TERMINAL: () => 'exit' }` (also `{ title }`, `'bell'`). A Collection item's element is the item's: a row click is the item's intent + `PARENT`, focus it from the parent with `focusWithin(...)`. In `sygnal/ui`, tabs, accordion, disclosure, popover and tooltip work in a terminal; the `dialog` behavior and `<Toaster />` don't yet (use a native `<dialog>`). Tests: `const t = createTerminal({ styles, width: 80, height: 24 }); run(App, { DOM: t.driver, TERMINAL: t.control })`, then `t.press('Enter')`, `t.type()`, `t.paste()`, `t.click(line, col)`, `t.wheel(line, col, rows)`, `t.keyHint()`, `t.commands`, and compare `t.frame()` (plain text) https://sygnal.js.org/renderers/terminal/
- A whole app in a Web Worker (experimental, the app unchanged: worker `const target = createWorkerTarget(self); run(App, { DOM: target.driver, STORE: target.remote('STORE', ['get']) })` from `sygnal/worker`, page `startBridge(new Worker(url, { type: 'module' }), root, { drivers: { STORE } })` from `sygnal/worker/page`; default actions are decided on the page from declarations, so use `events('keydown', { preventDefault: { key: 'Tab' } })` (true or a pattern, not a function); not yet: `sygnal/ui` dialogs/popovers, widgets, `fromReact`/`fromZag`, `ELEMENT` commands, layout reads, drag and drop, devtools, HMR) https://sygnal.js.org/renderers/off-main-thread/

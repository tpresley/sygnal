# Sygnal: UI parts (`sygnal/ui`), Menu / Select / Combobox, sortable lists, wizards, long lists, browser sources, library recipes

> A topic file of Sygnal's agent context. It assumes the core (`llms.txt`, or the sygnal-dev skill's `SKILL.md`: mental model, component anatomy, canonical forms, wiring rules, testing): read that first. Canonical forms only.

- Browser sources: `Card.browser = (state) => ({ seen: !state.seen && { intersection: '.cover', action: 'SEEN' }, dark: { media: '(prefers-color-scheme: dark)', action: 'DARK' } })` + `App.drivers = { BROWSER: makeBrowserDriver() }` (also `resize`, `storage`, `visibility`, `online`, `geolocation`; clipboard: `{ BROWSER: (s) => ({ copy: s.url, ok: 'COPIED', error: 'COPY_FAILED' }) }`; tests need no driver: `t.browser.intersect('.cover', true)`, `t.browser.media(query, true)`); `lazy(() => import('./Chart'))` imports at its first render; `{ when: 'visible' }` (or `'idle'`) defers it further; a failed import renders the owner's `onError` (`componentName === 'lazy'`), `Chart.load()` retries. Guide: `node_modules/sygnal/dist/guide/browser-sources.md`
- Long lists (from ~1,000 rows): `<VirtualCollection of={Row} from="rows" className="rows" estimateSize={32} aria-label="Rows" />` (Collection's props; it is itself the scroll container, a `div` with `role="list"`: give `.rows` a bounded height in CSS and put `className`, `role`, `aria-label` on it, never wrap it in your own scrolling `<ul>`; SYG430 means fix that height; `estimateSize` is the rows' real height in px (too low: blank space at the end of a fast scroll, SYG436); only rows in view have components, so keep row state in the array); jump with `ELEMENT: (s, index) => ({ scrollToIndex: '.rows', index })` or `{ scrollToId: '.rows', id }`. Guide: `node_modules/sygnal/dist/guide/virtual-collections.md`
- Reorderable list: `List.uses = { sort: sortable({ from: 'tasks', item: '.task', handle: '.grip' }) }` (mouse, touch, keyboard); items `<li className="task" data-id={state.id}><button className="grip" aria-label=… aria-describedby={context.sort.helpId}>` (context `sort: (s) => s.sort`; style from `context.sort.dragging` / `over` / `after`), host `<p id={state.sort.helpId} hidden>` instructions and `<p role="status" aria-live="assertive">{state.sort.message}</p>` (English defaults: "Dropped X at position 2 of 5.", "Reorder cancelled. X is back at position…"; a spec's exact wording: `messages: { lift, move, drop, cancel, stay }`, each `(label, position, count) => text`), save in `'sort.DROPPED': (state, { id, index, fromIndex }) => …` (the list is already reordered); two lists `from: ['todo', 'done']` + `data-list="todo"` on each container. HTML5 / file drops: `makeDragDriver`. Guide: `node_modules/sygnal/dist/guide/drag-and-drop.md`
- UI parts (`import { dialog, dialogAttrs, popover, popoverAttrs, tooltip, tooltips, tabs, tabsAttrs, accordion, accordionAttrs, disclosure, disclosureAttrs, Toaster } from 'sygnal/ui'`; native HTML, unstyled): behaviors over your own markup in `uses` (`Profile.uses = { profile: dialog({ dialog: '.profile', trigger: '.edit', close: '.cancel' }) }` → `state.profile.open`, `'profile.CLOSED'`; spread `dialogAttrs(state.profile, uid).trigger` / `.dialog` / `.title` / `.description` (ARIA, ids; `role="alertdialog"` on the dialog for an alert); for tabs/accordion/disclosure spread `tabsAttrs(state.tabs, uid).tab('general')` etc. for roles, ids and ARIA), every slice is the source of truth (Radix-style controlled): a reducer may write `{ ...state.faq, expanded: [id] }` or `{ ...state.profile, open: true }` and the element follows; start values through options (`dialog({ …, open: true })`), never the same key in `initialState`; refuse a close with a host entry returning `previousState` (`'profile.CANCEL': (state, e, next, { previousState }) => (state.dirty ? previousState : state)`; also `'profile.CLOSE'` for the close button / `method="dialog"` form); pass `open` (even `open: false`) to make a dialog / popover controlled: the browser never dismisses it, the behavior does (Escape, a press or focus outside → `'profile.CANCEL'` / `'filters.DISMISS'`, one per interaction, top layer first; an open Menu / Select / Combobox inside is the top layer), so a refused dismiss never flickers; a popover's own button: `popover({ popover: '.share', trigger: '.share-button' })` + spread `popoverAttrs(state.share, uid).trigger` / `.popover` (ARIA, ids; clicks → `'share.TOGGLE'`); add another opener by listing it in the option (`trigger: '.edit, .avatar'`), never with an intent action named `'profile.OPEN'` (it replaces the trigger, SYG118); `tooltips({ trigger: '.term', tip: '.term-tip' })` serves many triggers with one slice (each trigger's `aria-describedby` names its tip), and `<Toaster />` once + `EVENTS: event('TOAST', { text, kind, timeoutMs })` from anywhere (needs `makeTimerDriver()`). Guides: `node_modules/sygnal/dist/guide/ui/overview.md` (and `ui/dialog.md`, `popover`, `tooltip`, `tabs`, `accordion`, `disclosure`, `toaster`)
- Menu / Select / Combobox: `import { Select } from 'sygnal/ui/select'` (`sygnal/ui/menu`, `sygnal/ui/combobox`; each needs `@zag-js/vanilla` + its machine, e.g. `@zag-js/select@~1.45.0`): widget tags, `<Select className="size" label="Size" items={['S', 'M']} value={state.size} />` + `SIZE: DOM.select('.size').events('value-change').detail()` (Menu: `'select'`; Combobox also `'input-change'`), commands `{ open: '.size' }`; never `events('change')` (a native select's habit: no detail; SYG141); with `name` in a form they are form fields (the `form` behavior reads value and blur: `value={state.form.values.size}`); in a `<Portal>` too (events from a portal's content bubble to the component that renders it). Groups: `items={[{ group: 'Fruit', items: ['Apple'] }]}`. Menu items: `{ type: 'checkbox' | 'radio', value, label, checked }` (event `checked-change` `{ value, checked, type }`; keep `checked` in state), `{ href, value, label }`, a submenu `{ value, label, items }` (ArrowRight / ArrowLeft). Lists are `position: fixed` by default (`positioning={{ strategy: 'absolute' }}` inside a transformed ancestor). Escape hatch for one React/Preact component or a Zag machine: `fromReact(Comp, { events: { rate: 'onChange' } })` (`sygnal/react`) / `fromZag(menu, (api, props) => …, { events })` (`sygnal/zag`, `import * as menu from '@zag-js/menu'`) return widget tags; test them with `dom: 'real'`. Guides: `node_modules/sygnal/dist/guide/ui/menu.md` (`ui/select.md`, `ui/combobox.md`), `node_modules/sygnal/dist/guide/adapters.md`

## Wizards: `wizard()` + `<Outlet>` (experimental, outside semver)

- A multi-step flow, not a Switchable (its hidden steps keep running): `Flow.uses = { wizard: wizard({ steps: { source: { label: 'Source', valid: (s) => !!s.draft.source }, review: { label: (s, { state }) => s.bound ? 'Review and save' : 'Review', visit: { creating: false }, when: (s) => s.draft.kind != 'quick' } }, draft: { source: null }, next: '.next', back: '.back', reset: '.start-over', goto: '.goto', finish: 'CREATE' }) }`, and in the view `<Outlet of={{ source: Source, review: Review }} from="wizard" />`: only the current step exists (entering runs its BOOTSTRAP, leaving its DISPOSE and aborts its requests).
- A step's `state` is its own slice (kept across Back; its resources and `form` can't collide with another step's) plus `state.draft`, the flow's shared draft (`{ ...state, draft: { ...state.draft, source } }`; `draftKey: 'flow'` renames it). `visit` fields are set again on each entry and host mount (scratch). Predicates (`valid`, `when`, a function `label` / `dialog` / `visit`, a step's `discard`) get `(step, bag)`: the step's view (its initialState merged) and the host's bag (`bag.state`: the host's state); `dirty` gets `(step, stepName, bag)`. A step with `initialState` needs `isolatedState = true`. Types: `wizard<Draft, State, { review: ReviewState }>`, `WizardStepComp<ReviewState>` (a step that doesn't read the draft), `WizardStepComp<DefineState, { draft: Draft }>` (`{ draft?: Draft }` when it only writes it). A step's requests end with it: start an outcome's work in the outcome step's BOOTSTRAP, from the draft. Test a step alone: `t.sent('PARENT')`.
- A step moves the flow with a PARENT message: `{ wizard: 'NEXT' | 'BACK' | 'FINISH' }`, `{ wizard: 'GOTO', step }`, `{ wizard: 'GOTO', step, key, query?, draft? }` (a second record from inside the flow: starts over for that key at that step, past the guard; the URL gets only the key and `query`; the draft: `draft(state)` on the route entered, the message's `draft` merged over it), `{ wizard: 'RESET', draft? }` (`draft` merged over `draft(state)`) (a form step: `submit: 'DONE'`, `DONE: { PARENT: () => ({ wizard: 'NEXT' }) }`).
- Alternative steps (Analyze or Describe) share one stepper entry: `group: 'build'` on each, `groups: { build: { label } }`; render `state.wizard.stepper` (`{ name, label, status, step: the member that applies, steps }`; a stepper button's `data-step` is `e.step`, not the group's `e.name`). A final screen: `created: { outcome: true }`, entered by `{ wizard: 'GOTO', step: 'created' }`; while on it every step is `done`, Back and routes back into the steps are refused; entering the wizard again from another page starts a new flow (`restart: 'entry'`: any entry by a link or command does, finished or not; Back, Forward and a reload resume; `ROUTER.navigation()`). Dialog copy per step: `steps.x.dialog` (else the wizard's `dialog`) is `state.wizard.dialog`.
- `state.wizard`: `step`, `draft`, `local` (each step's slice), `visited`, `leaving`; derived: `steps` (`{ name, label, status: 'current' | 'done' | 'visited' | 'upcoming' | 'blocked' | 'skipped', current, reachable, valid }`), `canBack`, `canNext`, `index`, `count`, `last`. Stepper: `<ol aria-label="Progress">`, `aria-current={s.current ? 'step' : undefined}`, a `<button className="goto" data-step={s.name}>` only when `s.reachable && !s.current`. After a step change focus goes to the new step's `[data-wizard-focus]`, else its first h1/h2/h3.
- `key: (state, bag) => state.route.query.session` (or a prop: `(state, { recordId }) => recordId`): another key starts the flow over (no step renders against the old record); a key born mid-flow (none to a value) is adopted (the draft's untouched fields refilled from `draft(state, bag)`); null / undefined ("not mine") keep the flow. Start over: `reset` / `{ wizard: 'RESET' }` (url mode: to `resetTo(previousSlice, bag)`, else the first step's route).
- Unsaved changes: `dirty: (step, stepName, bag) => …` (or a step's own `dirty`, and `discard: (step, bag) => step`), `confirm: '.leave-dialog', leave: '.discard', stay: '.stay'` holds a navigation out of the flow (router `block`) and opens the `<dialog>`; Discard starts over (or `discard(w, bag)`) and goes. Moves inside the flow (to a step route for the flow's key, or any key while it has none) are never held.
- Step in the URL: `url: { route: 'newFilter', param: 'step', key: 'session', from? }` (`/filters/new/:step?session=`; `from(state, bag)` maps another route onto it): moves navigate, back/forward move between steps, a link to an unreachable step is replaced with the first incomplete step before it. A Start over `<a>` inside a step: `DOM.click('.start-over', { preventDefault: true })` + `{ wizard: 'RESET' }` (else two navigations).
- An app's pages, one alive at a time: `<Outlet of={PAGES} current={pageFor(state.route)} identity={pageIdentity(state.route)} fallback={NotFound} state={{ admin: 'pages.admin' }} />` (a per-page state map; pages not in it share the owner's state); or route mode `<Outlet of={PAGES} route={state.route} query={['session']} />`. Guide: `node_modules/sygnal/dist/guide/wizards.md` (online: https://sygnal.js.org/guide/wizards/).

## The bag: what every function over state gets

- Every function written over state takes `(subject, ...its own arguments, bag)`. The subject is the state it is about (the component's state, a behavior's slice, a wizard step's view, an item); the bag, always last, is what the view gets: `{ ...props, state, context, uid }` (`bag.state`: the component's whole state; in a behavior's or a wizard step's function, the host's).
- Handlers (`model`) also get `previousState`, `children`, `slots`, `now()` / `random()` / `uuid()` (and `signal` in an EFFECT). Derivations get the bag without those: `resources timers connections head browser route` (`(state, bag)`, recomputed when the state, the context or a prop changes: `Tasks.resources = { list: (s, { projectId }) => `/api/projects/${projectId}/tasks` }`, never a prop copied into state), `.context` entries (`(state, bag)`, `bag.context` the parent's), a behavior's `calculated` (`(slice, bag)`) and `timers` (`(slice, options, key, bag)`), `form()`'s schema function / `values` / `dynamic` (`(hostState, bag)`) and `request` (`(data, hostState, bag)`), an agent's `read` / `when` / `until` (`(state, bag)`) and `queries.run` (`(state, input, bag)`), `chat({ model })`.
- Unchanged: `calculated` fields and lenses (the state only: the cell is shared), a Collection's `filter` / `sort` and lens props (written in the view), `intent`, `onError`. A wizard's and a form's intent-side watches (the key, the leave guard, `dynamic`) get the whole bag (context and uid too) and run again when the context changes.
- 7.2 compatibility: before 7.2 a declaration static's 2nd argument was the context; `(s, { route })` still reads it until 8.0 (dev warning SYG458; a prop of the same name wins). Write `(s, { context: { route } })` (`sygnal-check --fix`).

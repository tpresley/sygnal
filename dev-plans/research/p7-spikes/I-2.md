# I-2: `sygnal-check lsp` in Neovim, Helix and JetBrains (LSP4IJ)

PLAN-7 §1.4 I-2, 2026-10-10, branch `p7-i2` (from `plan7-integration` at `35debf06`, after L-1/L-2). The server tested is this branch's `sygnal-check` 0.3.0, installed into the test project from `npm pack`.

**Short answers:**
- **Neovim 0.12.6: everything works,** with a 15-line config (`vim.lsp.config` + `vim.lsp.enable`). A headless script verifies all of it, three times (no editor settings, `settings`, `init_options`): diagnostics with exact ranges, a markdown hover, the quick fix, the suppress action, `source.fixAll.sygnal`, `relatedInformation` in the float, `workspace/configuration`, watched files, an added workspace folder, and a clean `shutdown`/`exit`.
- **Helix 25.07.1: works,** with `.helix/languages.toml`. Driven in a pseudo-terminal, verified from screen captures and the LSP traffic: diagnostics in the gutter, inline and in both pickers; a markdown hover; quick fix and suppress through `space a`; `config` reaching the server both ways; multi-root via `roots`; a clean exit. Three gaps:
  - `source.fixAll.sygnal` can't be reached: Helix never sends `context.only` and has no code-actions-on-save.
  - Helix doesn't show `relatedInformation` or `codeDescription`, and doesn't advertise either.
  - Helix sends `didChangeWatchedFiles` only for files it saves itself, not for changes made outside it.
- **IntelliJ IDEA CE 2025.2.5 + LSP4IJ 0.21.0: installed, not verified.** On first start the IDE blocks on JetBrains' **End User Agreement and Data Sharing dialog**, before any plugin loads. Accepting terms is something only the user may do, so I stopped there and closed the IDE.
  - Ready to run once the dialog is answered: an isolated-IDE launcher, the LSP4IJ server definition as config XML (format taken from LSP4IJ's source, **untested**), an importable LSP4IJ template directory, and a manual check list (§6).
  - LSP4IJ's client capabilities in §2 are read from its source (`ClientCapabilitiesFactory`), not captured.
- **No server bug found.** Nothing in `sygnal-check/src/lsp/` changed. Three small server-side suggestions are in §5.

## 3. Final configs

### Neovim (`I-2/nvim/init.lua`, minus the test switches)

```lua
vim.lsp.config('sygnal', {
  cmd = { 'npx', '--no-install', 'sygnal-check', 'lsp' },
  filetypes = { 'javascript', 'javascriptreact', 'typescript', 'typescriptreact' },
  root_markers = { 'sygnal-check.config.json', 'package.json', '.git' },
  -- settings = { sygnal = { strict = true } },  -- optional, answered on workspace/configuration
})
vim.lsp.enable('sygnal')
```

Verified as written. 0-S2's snippet was right apart from defaulting `settings`, which would override the config file.

### Helix (`I-2/helix/languages.toml`)

```toml
[language-server.sygnal]
command = "npx"
args = ["--no-install", "sygnal-check", "lsp"]
# config = { sygnal = { strict = true } }   # optional

[[language]]
name = "javascript"
language-servers = ["typescript-language-server", "sygnal"]
# likewise for "jsx", "typescript", "tsx"; add roots = ["package.json"] for one server root per package
```

Verified as a project-local `.helix/languages.toml`: Helix 25.07 loads it with no trust prompt. 0-S2's snippet was right. Use `config = { sygnal = { … } }` rather than the flat form: then both `workspace/configuration` and `initializationOptions` carry the settings. `typescript-language-server` wasn't installed; Helix skips a missing server silently and the Sygnal one still runs.

### JetBrains + LSP4IJ (untested)

- **GUI (documented by LSP4IJ):** Settings → Languages & Frameworks → Language Servers → `+`:
  - Server: name `Sygnal`, command `sh -c "npx --no-install sygnal-check lsp"`;
  - Mappings → File name patterns: `*.js` → `javascript`, `*.jsx` → `javascriptreact`, `*.ts` → `typescript`, `*.tsx` → `typescriptreact`;

## 5. Problems found

No server bug. Each finding was checked against the server code (`sygnal-check/src/lsp/server.js`):

1. **The docs link is invisible in both editors' hovers.** The markdown hover ends `[Docs](https://sygnal.js.org/reference/errors#syg110)`:
   - Helix renders only the text "Docs" (screen);
   - Neovim's markdown float conceals the URL too;
   - neither editor renders `codeDescription`, so neither shows the docs URL anywhere.

   **Suggestion (server, small):** make the link text the URL, e.g. `[sygnal.js.org/reference/errors#syg110](https://…)`, or append the bare URL. I didn't change it, because it's presentation and not a bug.
2. **`relatedInformation` and `codeDescription` go to clients that don't advertise them** (Helix advertises neither; Neovim doesn't advertise `codeDescriptionSupport`). This is harmless: both clients ignore the fields, and Neovim even round-trips them. It is a small departure from "don't assume a capability you didn't check" (I-2). Stripping them per capability would be a few lines in `apply()`. Optional.
3. **`source.fixAll.sygnal` is unreachable in Helix**, because the server offers it only when `context.only` asks for it (on purpose: VS Code fires automatic requests constantly). Options:
   - document `:sh npx sygnal-check --fix %` followed by `:reload` as the Helix route (proposed in the docs text);
   - or also offer fix-all in an explicit (`triggerKind: 1`) request without `only`.
4. **Helix answers the first `workspace/configuration` ≈1.4–1.6 s late**, together with its first `didOpen`. The server's `configurationTimeout` is 2 s, so the margin is ≈0.4 s on this machine. Missing it is harmless:
   - the first check then uses `initializationOptions`, which in Helix is the same `config` table;
   - Helix's `didChangeConfiguration` (≈2.0 s) re-asks anyway.

   The visible cost is the ≈2 s to first diagnostics in Helix.
5. **Helix watched files:** events come only for files Helix itself writes, not for external changes such as `git checkout` or a formatter run outside the editor. The server already re-reads the disk on every check, so the next edit or save in Helix catches up. Docs note only.
6. **A file outside every workspace folder gets no findings.** Helix `didOpen`s such a file to the running server without adding a folder. This is consistent with the README ("one project per workspace folder") and the same in every client. Docs note: open the editor in the project, or set Helix `roots`.
7. **Neovim sends `workspace/didChangeConfiguration` right after `initialized`** when `settings` is set. The server then asks for the configuration twice, concurrently (identical answers). Harmless.

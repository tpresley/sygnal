# Sygnal: what the core shortened, in full

It assumes the core (`llms.txt`).

> Reactive component framework (Cycle.js Model-View-Intent, JSX views, xstream streams). `npm i sygnal`; Vite: `import sygnal from 'sygnal/vite'`, `plugins: [sygnal()]`; entry: `run(App)`. This file shows only the canonical forms. Strict mode (`sygnal-check --strict`, runtime `strict: true`) flags other forms as SYG5xx; forms 6.0 removed (positional views, `'A | SINK'` keys, `CHILD.select('Name')`, `.components`, `.peers`, `component()`) are SYG612: https://sygnal.js.org/guide/migrating-to-6/. 7.0 changes reducer timing (outputs see the state after STATE) and child lifetimes: https://sygnal.js.org/guide/migrating-to-7/
- There is one state tree. A child sees its parent's whole state, or a slice with `state="key"` (or a path: `state="settings.rules"`, `"boards[0].title"`). A Collection item sees one array element.
- A child belongs to the record its `state` points at (Sygnal 7): when a path or `byId()` target changes, or its record is deleted, the old child is disposed (its DISPOSE gets its last state; its requests, timers and subscriptions are cancelled) and a new one mounts with fresh local state and new DOM (focus and typing inside it are lost). So `<Workspace state={byId('projects', selected.id)} />` needs no key. Same for Collection/VirtualCollection `from` and Switchable `state`. A stable `key` doesn't keep a child across a target change (keep that state in the parent); a custom lens needs `key={record.id}`. Sygnal 6 fixes bindings at mount: use `key={selected.id}` there (SYG454).
- Every side effect is a sink of a model entry (STATE, EVENTS, PARENT, EFFECT, custom drivers). JSX never has event handlers (`onClick`). A view may return `null` (nothing) or a string or number (text).
- Streams are xstream, not RxJS: `import { xs } from 'sygnal'` (not `import xs from 'xstream'`, the module object under Node ESM / Vite 8: SYG302). An intent's DOM selectors only see the component's own JSX, never a child component's.
- Reducer `(state, data, next, props)`. `data` is the action stream's value. `next('ACTION', data?, delayMs = 10)` dispatches another action of this component only (a child's `next('X')` never reaches a parent's `X`: SYG117; send it up with `PARENT` / `EVENTS`) `delayMs` after the call, whenever it is called: also later, from a timer or callback in an EFFECT (HTTP goes through `makeFetchDriver`, not `fetch` + `next()`). `props` holds the parent's props plus `state`, `context`, `children`, `slots`.
- Model entry: a function is the STATE reducer. An object `{ STATE, EVENTS, PARENT, EFFECT, LOG, <DRIVER>: fn }` maps each sink to a `(state, data, next, props)` function whose return value goes to that sink. `<SINK>: true` forwards `data` as-is.
- **STATE runs first in every entry (Sygnal 7)**; every other sink gets the committed state, calculated fields included: `INC: { STATE: s => ({ ...s, n: s.n + 1 }), PARENT: s => ({ n: s.n }) }` (`s.n + 1` would count twice). The state from before the action is `props.previousState` (4th argument): read it for a value STATE cleared or deleted, and in a guard that admits the action: `HTTP: (s, d, next, { previousState }) => (previousState.status === 'working' ? ABORT : { url: '/api/work', ok: 'DONE' })` (`s.status` is already `'working'` there; keep the guard, since STATE's `ABORT` doesn't cancel other sinks; SYG256). The tradeoff: payloads read `state`, guards read `previousState`. When STATE removes the component's own state (`() => undefined`), its other sinks get its last state. Behaviors: the slice and `props.state` are after STATE, the old slice is `props.previousState[key]`. Code for 6 and 7 reads old values as `props.previousState ?? state`. Upgrading 6.x code (every reducer saw the old state): turn on the timing audit, `renderComponent(C, { timingAudit: true })` or `sygnal({ diagnostics: { timingAudit: true } })`, and decide each SYG257. Guide: `node_modules/sygnal/dist/guide/migrating-to-7.md` **The clock and randomness** come from the handler's 4th argument, never the globals: `ADD_TASK: (state, title, next, { now, uuid }) => ({ ...state, tasks: [...state.tasks, { id: uuid(), title, created: now() }] })` (also `random()`; EFFECTs too, also after an `await`). They are `Date.now()` / `Math.random()` / `crypto.randomUUID()`, but tests fix them (`renderComponent(C, { now: Date.parse('2026-01-01'), random: 1, uuid: true })`: fixed clock, seeded random, ids `00000000-0000-4000-8000-000000000001`, `…002`) and a replay supplies the recorded values. `Date.now()` / `new Date()` / `Math.random()` / `crypto.randomUUID()` in a STATE reducer is SYG258 (any handler: SYG509, strict); `sygnal-check --fix` rewrites them. A prop named `now` / `random` / `uuid` shadows them.
- **A chat conversation** is the `chat` behavior, never hand-rolled: `Chat.uses = { chat: chat({ agent: false, form: '.ask', prompt: '.prompt', stop: '.stop', regenerate: '.retry' }) }` → `state.chat` (`messages`, `prompt`, `draft`, `status`, `error`); `run(App, { LLM: makeChatDriver({ transport }) })`; tests `await t.stream('LLM', ['Hel', 'lo'])`. **Never put a provider API key in browser code** (SYG670): the browser calls your server (`uiMessageStream('/api/chat')`).
- One-off LLM requests, the `agent` static (tools an LLM may call), decisions (`decide()`), pages and chat cards a model composes from your parts (`defineCatalog`, `compose`, `chat({ ask })`): read `llms/ai.md` first.
- **ABORT**: from a STATE reducer, the state is unchanged (returning the identical `state` object also is: no emission, no render; except for an action triggered by an `input`/`change` event, which re-renders so a refused controlled field shows the state's value again); from any other sink, nothing is sent.
- **React to a state change** (save a draft, reload when a filter changes): `SAVE: STATE.watch(state => state.text).compose(debounce(1000))` in intent emits the selected value each time it changes (compared structurally; `{ immediate: true }` emits the current one first (a value set at mount), in the mount flush before BOOTSTRAP: reset in initialState, not BOOTSTRAP; a Collection item watches its own state). Not `STATE.stream` + `dropRepeats()`.
- **UI parts, lists, browser input: never hand-roll these**, read `llms/ui.md` first: dialog, popover, tooltip, tabs, accordion, disclosure, toasts (`sygnal/ui` behaviors in `uses` + `<Toaster />`); Menu / Select / Combobox (`sygnal/ui/menu|select|combobox` widget tags); one React or Zag component (`fromReact`, `fromZag`); drag to reorder (`sortable`); 1,000+ rows (`<VirtualCollection>`); visibility, media queries, resize, clipboard (`browser` static + `makeBrowserDriver()`), `lazy(…, { when: 'visible' })`; tested recipes for charts, rich text, code editors, carousels, data grids, TanStack Table, icons, i18n.
- Untrusted or model-written components in a QuickJS sandbox (`sygnal/sandbox`, experimental): `llms/sandbox.md`.

Finish the checkout form in `src/App.jsx`: validate it, let the customer order several items, and place the order with the server. The markup is there; nothing is validated or sent yet.

- The form (`form.checkout`) has, in this order: "Full name", "Email" and "ZIP code" text fields; the items; a "Promo code" text field; and a "Place order" submit button. Each item is a `<fieldset class="item">` whose legend reads "Item 1", "Item 2", … in order, with a "Product" `<select>` (options "Choose…" with value `""`, then "Notebook", "Pen set" and "Backpack", each with its text as its value), a "Quantity" `<input type="number">` and a "Remove" button. "Add item", after the items, adds an item with no product and quantity 1. The form starts with one such item.
- "Remove" removes its item (the others keep what was entered in them, and the legends renumber). It is disabled while there is only one item.
- Every field has an accessible name that starts with its label ("Product" and "Quantity" in each item). Element ids must be unique on the page.
- Rules and messages: Full name must not be blank: "Enter your name." Email must look like an address, text@text.text without spaces: "Enter a valid email address." ZIP code must be exactly 5 digits: "Enter a 5-digit ZIP code." Each item needs a product: "Choose a product." and a whole-number quantity from 1 to 10: "Enter a quantity from 1 to 10." The promo code is optional; when given it must be 4 to 12 letters or digits: "Promo codes are 4 to 12 letters or digits." Values are checked with surrounding spaces removed.
- A field's message appears when the user leaves the field with an invalid value, or on "Place order". From then on it follows the typing: it disappears as soon as the value is valid and comes back when it isn't. An invalid field has `aria-invalid="true"` and its `aria-describedby` points at the element holding its message (and only there is that message shown). A valid field has no `aria-invalid="true"` and shows no message.
- "Place order" with errors shows every message, moves keyboard focus to the first invalid field in form order, and sends nothing.
- "Place order" with valid values sends `POST /api/orders` with a JSON body like `{ "name": "Ada Lovelace", "email": "ada@example.com", "zip": "02139", "items": [{ "product": "Notebook", "quantity": 2 }], "promo": "" }`: exactly these keys, the text values without surrounding spaces, the quantities as numbers, the items in form order, and `""` for an empty promo code. While it is pending the button reads "Placing order…" and is disabled, and placing the order again sends nothing. The form never reloads the page.
- The server answers `201` with `{ "id": "A-1001" }`: show "Order A-1001 placed." in `.done`.
- The server can refuse the order with `422` and a body like `{ "errors": [{ "path": ["items", 1, "quantity"], "message": "Only 3 left in stock." }, { "path": ["promo"], "message": "This promo code has expired." }] }` (`path` is a field name; for items, the item's position from 0 in the order that was sent, then the field). Show each message on its field at once, exactly like a validation message, and move focus to the first of those fields in form order. Changing a field removes its server message.
- Any other failure (another status, or a network error): show "Could not place the order. Try again." in an element with `role="alert"`, keep everything that was entered, and enable "Place order" again. Placing the order again removes the message.

Finish this signup page: make its fields accessible, validate both forms, and confirm the signup in a dialog.

- Every field has an accessible label that starts with its visible name: "Name", "Email" and "Password" in the signup form (`form.signup`), "Email" in the newsletter form (`form.newsletter`). Use a `<label>` tied to the field, or `aria-labelledby`. Element ids must be unique on the page.
- The password hint (`.hint`, "At least 8 characters.") describes the password field: the field's `aria-describedby` always includes the hint's id.
- "Create account" checks the signup form. Name must not be blank: "Enter your name." Email must look like an address, text@text.text without spaces: "Enter a valid email address." Password needs at least 8 characters: "Use at least 8 characters." Each message is shown in a `<p class="error">` inside the invalid field's `.field`; valid fields show none. An invalid field has `aria-invalid="true"` and its `aria-describedby` includes the message's id (for the password field: the hint's id and the message's id). A valid field has no `aria-invalid="true"`.
- Messages appear only after the first "Create account". From then on they follow the typing: a field that becomes valid loses its message and `aria-invalid`, and one that becomes invalid gets them.
- When the form has errors, "Create account" moves keyboard focus to the first invalid field, in form order. Typing never moves focus.
- The newsletter form works the same way for its own Email field and "Subscribe": same rule, same message, its own message element and id, and focus moved to its field when it is invalid. When it is valid, `.subscribed` reads "Subscribed ada@example.com." (with the address typed). The two forms never show or clear each other's messages.
- Neither form may reload the page: prevent the browser's default form submission.
- When the signup form is valid, "Create account" opens a confirmation in a native `<dialog class="confirm">`, opened as a modal (`showModal()`), reading "Create the account for ada@example.com?" (the email typed), with two buttons, "Confirm" and "Cancel". Cancel closes the dialog. Confirm closes it and shows "Account created for Ada Lovelace." in `.done` (the name typed). The browser can also close the dialog (Escape); after that the page keeps working, so "Create account" opens it again.

jsdom, which the tests run in, has no `showModal()` or `close()`. The acceptance tests add them to `HTMLDialogElement.prototype`, behaving like a browser: `showModal()` sets `open` and moves focus into the dialog; `close()` removes `open`, then fires a `close` event on the dialog (it doesn't bubble); Escape in a modal dialog fires `cancel` and then closes it.

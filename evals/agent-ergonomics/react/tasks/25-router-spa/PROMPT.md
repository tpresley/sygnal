Give this task app real URLs. Its three pages (the task list, a task, and the task's edit form) already work, but they are switched by buttons and the URL never changes. Keep their markup apart from the changes below (each page's `<h1>`, the form's `input[name="title"]` and "Save" button).

- Routes: `/` is the list, `/tasks/<id>` a task, `/tasks/<id>/edit` its edit form. Any other URL, and a task id that doesn't exist (`/tasks/99`, `/tasks/99/edit`), shows a not-found page whose `<h1>` is "Not found". Opening the app at any of these URLs shows that page.
- Navigation uses real links (`<a href>`), not buttons: "All tasks" in the `nav` (on every page) links to `/`; each task in `ul.tasks` is a link with the task's title to `/tasks/<id>`; on a task's page "Edit" links to `/tasks/<id>/edit`; on the edit form "Cancel" links to `/tasks/<id>`. Clicking a link changes the URL and the page without reloading the app.
- The browser's Back and Forward buttons move through the pages visited in the app.
- The document title follows the page: "Tasks" on the list, "<task title> · Tasks" on a task (for example "Book the venue · Tasks"), "Edit <task title> · Tasks" on its edit form (with the saved title), "Not found · Tasks" on the not-found page.
- "Save" on the edit form saves the title and goes to the task's page, which shows the new title.
- Unsaved changes: when the edit form's field differs from the saved title, leaving the form any other way (a link or the browser's Back button) does not happen right away. Instead `div.confirm` appears inside the page with the text "Discard your changes?" and the buttons "Leave" and "Stay" (don't use `window.confirm`). While it is shown, the URL and the page stay as they were. "Leave" closes it and completes the navigation the user tried; the change is discarded, so the task keeps its saved title. "Stay" closes it and stays on the form with the typed text kept.

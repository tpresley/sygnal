Make this item browser load its data from the server, keep it cached, and let the user rename an item. Opening an item and "Back to list" already work; nothing is loaded yet.

- The list loads with `GET /api/items`, which answers JSON like `[{ "id": 1, "title": "Alpha" }, { "id": 2, "title": "Beta" }]`. Show one `<li>` per item in `ul.items`, each holding a `button.open` whose text is the title (clicking it opens the item, as now).
- An item loads with `GET /api/items/<id>`, which answers JSON like `{ "id": 1, "title": "Alpha", "body": "The first item." }`. Show the title in `.item-title` and the body in `.item-body`, inside `.detail`.
- The first time the list or an item is shown, `.status` shows "Loading…" until it arrives, and none of its data is shown (in the detail view, nothing of any other item either). After that it is cached: showing it again displays the cached data at once, never "Loading…". If its data arrived less than 2 seconds ago, no request is made. Otherwise it is reloaded in the background: `.status` shows "Updating…" while that request is in flight, then the new data replaces the old. In every other case `.status` is empty.
- When an item is shown, an "Edit" button opens `div.edit` with an `input[name="title"]` holding the item's title and a "Save" button. Save sends `PUT /api/items/<id>` with the JSON body `{ "title": "<the typed title>" }`; the server answers with the updated item.
- After a successful save, `div.edit` closes and the item and the list show the new title. The saved item and the list are then out of date, so each is reloaded the next time it is shown (or right away, if it is on screen), even if its data arrived less than 2 seconds ago, in the background as above.
- If a save fails (a non-2xx status or a network error), `.save-error` shows "Could not save the item." and `div.edit` stays open with the typed title. Saving again removes the message (it comes back if that save fails too).
- Responses can arrive in any order: the response to an older request must never replace newer data.

## Method and limits

**Phase attribution.** Every interval between two consecutive transcript events (tool call, tool result, assistant text) is given to the later event: generating a tool call and running it both count toward that call's phase; planning text in the same message counts toward the message's first call. Phases:

- `orient`: reading the starter and app files, `ls`/`find`/`cat` in the trial dir, other shell commands.
- `learn`: Skill tool, reading skill files, reading `node_modules/<framework>` source, `.d.ts` or docs, web docs.
- `implement`: Write/Edit (or shell writes) to non-test files.
- `test-authoring`: writing, reading or deleting the agent's own test files.
- `verify`: build/test runs (lib/transcript.mjs `isRunCommand`), ad-hoc `node` checks, driving the app in the browser pane.
- `debug`: everything after a failed build/test run until the next passing run (re-runs, reading errors, fixes), when the failure matches no known defect.
- `tooling-friction`: the same span when the failure matches a known defect in the catalog, plus any command the environment refused (HARNESS-GUARD).
- `think`: assistant text with no tool call.
- `report`: writing and delivering the final report (SubagentHandback and after).
- `other`: unclassified tools; reported as the unattributed share.

Limits:
- Model "thinking" before a call is charged to that call. The cost of ingesting a large tool result (e.g. the 12 KB skill injection) lands on the *next* call, usually `orient`. So `learn` undercounts the skill's real cost; the context-token rows capture the rest.
- `debug` / `tooling-friction` start at the failed run and end at the next run that passes and was issued after the failure. Deleting a failing test and re-running counts as green. A failure that is never followed by a green run is charged to the end of the trial (column "Never green").
- Pass/fail of a run is read from vitest / vite summaries first, then the exit code (output is often piped through `tail`, which hides it).
- Catalog matching is regex-based. 'suspect' entries (G-015, G-016: `waitForState timed out`) count as friction only when the agent's report names the issue; otherwise they are agent-mistake debug time. Report matching can also pick up mentions that aren't complaints (e.g. explaining the isolation trap in task 07).
- **Headless trials** (run-trial.mjs): cost, billed tokens (input + output + cache read + cache creation over all turns), output tokens and the agent-reported duration come from the run's final `result` event, so they are exact. Billed tokens are much larger than peak context, because every turn re-reads the cached context.
- **Output tokens are not reliable in subagent transcripts**: each streamed message records a partial `output_tokens` (often 16). Context size (input + cache read + cache creation) is reliable, so the token metric used is peak context per trial (≈ the final context the Agent tool reports), plus cache-creation tokens (new tokens entering context).
- Wall time is first to last transcript timestamp; it matches the recorded `wallSeconds` within a second for all but a few trials.
- Small n (5 trials per task and arm); differences under ~5 s per trial are within noise.
- **Process kills refused by the guard** (G-127, `processGuard: 1`): react-30-t1 (1: killall); react-30-t2 (2: pkill, xargs kill); react-30-t5 (1: pkill); react-31-t2 (1: pkill); react-31-t3 (1: pkill); react-31-t4 (2: pkill); react-31-t5 (1: pkill); react-32-t1 (1: pkill); react-32-t4 (1: pkill); react-32-t5 (1: killall); sygnal-32-t4 (1: pkill); react-33-t1 (1: pkill); react-33-t2 (1: pkill); react-33-t4 (1: pkill); sygnal-33-t2 (1: pkill); react-34-t3 (1: pkill); react-34-t5 (1: pkill); sygnal-34-t5 (1: pkill). No other process was affected; the attempt costs that trial a refused call.
- **Built-in skills** (D234): available in every trial (`skillGuard` 0, the condition before 4-E2): agents could call the CLI's own skills (`run`, `dataviz`, …); the calls are listed under "Other skills invoked". Runs from 4-E2 on block them, so compare such numbers across that change with care.
